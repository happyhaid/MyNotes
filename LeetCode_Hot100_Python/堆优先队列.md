# 让堆可以比较节点大小（不改 __lt__ 的写法见 Python3 写法二）
ListNode.__lt__ = lambda a, b: a.val < b.val  #改正这里为lambda a, b: a.val > b.val 就能偷梁换柱骗过heapq 变成大顶堆

class Solution:
    def mergeKLists(self, lists: List[Optional[ListNode]]) -> Optional[ListNode]:
        cur = dummy = ListNode()  # 哨兵节点，作为合并后链表头节点的前一个节点
        h = [head for head in lists if head]  # 把所有非空链表的头节点入堆
        heapify(h)  # 堆化
        while h:  # 循环直到堆为空
            node = heappop(h)  # 剩余节点中的最小节点
            if node.next:  # 下一个节点不为空
                heappush(h, node.next)  # 下一个节点有可能是最小节点，入堆  
            cur.next = node  # 把 node 添加到新链表的末尾
            cur = cur.next  # 准备合并下一个节点
        return dummy.next  # 哨兵节点的下一个节点就是新链表的头节点

# Python heapq、ListNode比较、lambda、高阶函数笔记

## 1. heapq 默认如何比较元素

heapq 是一个堆结构，它维护堆的过程中需要不断判断：

```python
a < b
```

因此 heapq 不关心对象内部有什么属性，只会调用元素本身的 `<` 比较规则。

例如：

```
import heapq

h = []
heapq.heappush(h, 3)
heapq.heappush(h, 1)
```

这里比较的是：

```
3 < 1
```

因为 int 类型已经实现了比较方法。

------

如果把 ListNode 放入堆：

```
heapq.heappush(h, node1)
heapq.heappush(h, node2)
```

heapq 为了维护小顶堆，会执行：

```
node1 < node2
```

Python 会进一步调用：

```
node1.__lt__(node2)
```

但是普通的 ListNode：

```
class ListNode:
    def __init__(self, val):
        self.val = val
```

没有定义：

```
__lt__()
```

所以 Python 不知道两个节点如何比较：

```
node1 < node2
```

因此报错：

```
TypeError:
'<' not supported between instances of 'ListNode' and 'ListNode'
```

------

## 2. ListNode.**lt** 的作用

解决上面的问题，就是告诉 Python：

> ListNode 对象之间比较大小时，应该比较 val。

添加：

```
ListNode.__lt__ = lambda a, b: a.val < b.val
```

等价于：

```
def __lt__(self, other):
    return self.val < other.val
```

之后：

```
node1 < node2
```

实际执行：

```
node1.val < node2.val
```

于是 heapq 就知道如何维护堆了。

------

注意：

```
ListNode.__lt__
```

只修改 ListNode 类的比较规则。

不会影响其他类型：

```
3 < 5
```

仍然调用：

```
int.__lt__()
```

------

## 3. heapq 处理自定义对象的两种方式

### 方法1：给对象添加 **lt**

堆中存：

```
[
    node1,
    node2,
    node3
]
```

heapq 比较：

```
node1 < node2
```

调用：

```
ListNode.__lt__()
```

最终比较：

```
node1.val < node2.val
```

------

### 方法2：包装成 tuple

不修改 ListNode：

```
h = [
    (node.val, index, node)
]
```

heapq 比较 tuple：

```
(val, index, node)
```

tuple 比较规则：

1. 比较第一个元素
2. 如果相等，比较第二个元素
3. 如果还相等，比较第三个元素

例如：

```
(1,0,nodeA)
(1,1,nodeB)
```

比较：

```
1 == 1

继续比较

0 < 1
```

已经决定大小，因此不会执行：

```
nodeA < nodeB
```

所以不会触发 ListNode 比较错误。

## 4. lambda、本质和高阶函数

lambda 创建的是一个函数对象：

```
x = lambda a,b:a+b
```

等价：

```
def x(a,b):
    return a+b
```

lambda 不会自动执行。

自己调用：

```
x(1,2)
```

才执行。

如果传给其他函数：

```
filter(lambda x:x%2==0, nums)
```

lambda 会作为参数传进去，由 filter 内部调用。

------

## 5. filter、map、reduce 内部调用 lambda

### filter

作用：筛选。

```
filter(lambda x:x%2==0, nums)
```

内部类似：

```
def my_filter(func, nums):
    result=[]

    for x in nums:
        if func(x):
            result.append(x)

    return result
```

filter 调用：

```
func(x)
```

lambda 返回 True/False。

------

### map

作用：转换。

```
map(lambda x:x*x, nums)
```

内部类似：

```
def my_map(func, nums):
    result=[]

    for x in nums:
        result.append(func(x))

    return result
```

------

### reduce

作用：累计。

```
reduce(lambda a,b:a+b,[1,2,3,4])
```

内部类似：

```
def my_reduce(func, nums):
    result=nums[0]

    for x in nums[1:]:
        result=func(result,x)

    return result
```

执行：

```
1

1+2=3

3+3=6

6+4=10
```

## 6. 链表什么时候需要 cur.next=None

判断：

> 当前连接的节点后面是否还有旧链表。

如果节点本身就是原链表尾节点：

```
1 -> 2 -> 3 -> None
```

连接：

```
cur.next=node
```

因为：

```
node.next=None
```

所以不用额外处理。

如果连接的是中间节点：

```
1 -> 2 -> 3
```

只想留下：

```
cur -> 1
```

但是：

```
1.next
```

仍然指向：

```
2 -> 3
```

需要：

```
node.next=None
```

断开旧连接。

判断口诀：

```
节点后面还有旧链表？
    |
    有 → next=None
    |
    无 → 不需要
这样顺序就是：

**heapq为什么报错 → 为什么需要lt → 两种解决方法 → lambda → 高阶函数 → 链表指针**

更符合你实际学习时的思考路径。
```
