## 1. `(?:xxx)` 非捕获分组

### 为什么和多选挂钩

正则`|`（或）优先级最低，必须用括号把多个选项打包成整体，前面的符号（空格、量词）才能作用全部选项。

普通括号`()`打包多选会自动生成捕获分组；

`(?:)`保留**打包、多选**能力，关闭捕获，不会多出无用`group`。

### 特点

能打包多分支，不能用`group(序号)`提取括号内内容。

### 业务示例

```
\n\s*(?:Thought:|Action:|Observation:)
```

打包 3 个关键词实现三选一，空格统一修饰所有关键词，无多余分组。

## 2. `(?=xxx)` 正向先行断言

只校验右侧文本，用来划定匹配边界；断言匹配到的字符不会纳入最终匹配结果，没有打包功能。

若断言内部需要多选，依旧要用括号打包，内层搭配`(?:)`防止多余分组。

### 特点

只定位边界，不占用字符；和分组打包无关。

## 3. `.*?` 非贪婪匹配

不属于括号语法。开启`re.DOTALL`后`.`包含换行；末尾`?`让匹配尽可能短，遇到终止条件立刻停止，避免贪婪匹配拉取过多内容。

## 4. 三者核心分工

1. `?:`：负责多选打包，管控是否生成分组；
2. `?=`：负责边界判定，管控字符是否进入最终结果；
3. `.*?`：负责控制匹配长度，和分组、边界无关。

## 5. 项目正则嵌套逻辑

```regex
(?=\n\s*(?:Thought:|Action:|Observation:)|\Z)
```

外层`?=`：限制结束边界；

内层`?:`：打包多选，避免多余分组。两者功能独立，不可互相替代。

# 正则解析参数中的引号问题

## 1. `([^"]*)` 为什么还要禁止引号？

示例：

```python
r'(\w+)="([^"]*)"'
```

结构：

```
(\w+)   =   "   ([^"]*)   "
参数名       左引号   内容      右引号
```

作用：

- `(\w+)`：匹配参数名
- `="`：匹配等号和开始双引号
- `([^"]*)`：匹配参数值内容
- `"`：匹配结束双引号

关键理解：

- 外层的 `"` 负责定义字符串边界
- `[^"]*` 负责限制内容不能包含双引号，防止提前结束

例如：

```
name="Tom", age="18"
```

如果使用：

```
(.*)
```

因为 `.*` 是贪婪匹配，会尽量多匹配：

```
Tom", age="18
```

导致两个参数被当成一个值。

所以：

```
"        "
↑        ↑
边界     边界

[^"]*
只能匹配中间非引号内容
```

二者作用不同：

- `"`：确定范围
- `[^"]*`：防止越界

------



# 2. 当前正则只支持双引号字符串

代码：

```
kwargs = dict(re.findall(r'(\w+)="([^"]*)"', args_str))
```

只能匹配：

```
name="Tom"
```

不能匹配：

```
name='Tom'
```

原因：

正则写死了：

```
="
```

表示必须是：

```
= "
```

而不是：

```
= '
```

------

# 3. 如何同时支持单引号和双引号？

可以写：

```
r'''(\w+)=["']([^"']*)["']'''
```

其中：

```
["']
```

表示：

```
" 或 '
```

例如：

```
name="Tom"
age='18'
```

都可以匹配。

------

# 4. 当前代码不是完整 Python 解析器

这段代码：

```
re.findall(r'(\w+)="([^"]*)"', args_str)
```

只是解析一种简单格式：

```
tool_name(
    arg1="value1",
    arg2="value2"
)
```

优点：

- 简单
- 适合 Agent 工具调用格式

缺点：

- 不支持完整 Python 字符串规则
- 不支持复杂转义
- 不支持嵌套结构

------
